# Чек-лист релиза (ЦОИФТ)

Форма заполняется на каждый релизный объект. В реальной работе — это шаблон ЦОИФТ,
согласованный с заказчиком; здесь он нужен, чтобы отработать порядок подготовки релиза.

## 1. Сведения о релизе

| Поле | Значение |
| --- | --- |
| Название релиза | habits-service vX.Y.Z |
| Релизная ветка | release/X.Y.Z |
| Тег | vX.Y.Z |
| Дата релиза | |
| Ответственный тестировщик | |
| Ссылка на задачу (Jira) | |
| Ссылка на Allure-отчёт | |

## 2. Состав релиза

- [ ] Перечень задач, входящих в релиз, собран и согласован
- [ ] Для каждой задачи приложены результаты тестирования
- [ ] Изменения схемы БД (Flyway-миграции) отражены в релизной заявке
- [ ] Новые Kafka-топики и события согласованы с командой интеграций
- [ ] Версия API совместима с потребителями (обратная совместимость проверена)

## 3. Проверки до релиза

- [ ] Smoke-набор зелёный (`mvn test -Dcucumber.filter.tags=@smoke`)
- [ ] Регрессионный набор зелёный (`mvn test`)
- [ ] Проверки данных в PostgreSQL выполнены (нет висячих записей, уникальные ключи соблюдены)
- [ ] Сценарии Kafka пройдены (`mvn test -Pkafka`)
- [ ] UI-проверка релизных задач выполнена (если релиз содержит фронтенд)
- [ ] Дефекты критичности Blocker/Critical закрыты, остальные — согласованы с продуктом

## 4. Релизные объекты

- [ ] Ветка `release/X.Y.Z` создана и запушена
- [ ] Тег `vX.Y.Z` создан и запушен
- [ ] Артефакт сборки приложен к релизному объекту
- [ ] Allure-отчёт приложен к релизному объекту
- [ ] Заполнена заявка ЦОИФТ и получено согласование

## 5. После релиза

- [ ] Выполнена проверка на среде после выката
- [ ] Ветка `release/X.Y.Z` влита в `master` и `develop`
- [ ] Тег `vX.Y.Z` проставлен на `master`
- [ ] Дефекты, найденные после релиза, заведены и распределены
